# LAC HUB + BUILD — 로그인 진입 화면 정리 (테스트 저장소 전용)

**운영 `LAC-HUB` 및 독립 `BUILD` 저장소에 지금 적용하지 마세요.** `LAC-BUILD-TEST` 테스트 저장소에만 넣는 전체본입니다.

## 변경 범위
- HUB의 **로그아웃 상태 로그인 화면에서만** 「새 회사를 개설하시나요? · 코드 입력」 항목 제거.
- 그 아래 안내 문구를 Discord 계정과 HUB/BUILD 로그인 공유를 설명하는 문구로 변경.
- 로그인 후 회사 미설정 사용자가 이용하는 기존 회사 생성/회사 개설 코드 확인 화면 및 서버·DB 권한 검사는 유지.
- 기존 회사, 로그인, 게시글, BUILD 기능·경로, Discord 봇, Supabase DB·정책·환경변수 **수정 없음**.
- `scripts/check-login-cleanup.mjs`라는 읽기 전용 UI 회귀 검사 추가.

## 뒤로가기에서 나타나는 「회사 정보를 불러오는 중입니다」 진단
HUB와 BUILD는 같은 도메인에 있으나 별도의 앱 엔트리입니다. BUILD에서 브라우저 뒤로가기로 HUB 문서를 다시 열면, HUB의 `boot()`가 세션과 회사 관련 권한/데이터를 다시 확인한 후 `state.ready=true`로 전환합니다. 준비 중에는 `renderStartupLoading()`이 표시됩니다. 이는 데이터 접근 제어와 관련 있으므로 이번 UI 정리본에서 로딩 화면을 무작정 제거하거나 확인 전 데이터를 표시하지 않았습니다. 완전히 연속적인 화면 전환을 위해서는 **두 앱의 공통 화면 셸/라우팅 개편** 혹은 별도로 검증한 로딩 최적화가 필요합니다. 이번 테스트 ZIP은 로딩 현상을 고친 파일이 아닙니다.

## 적용 및 확인
1. 기존 `LAC-BUILD-TEST` 저장소의 **백업/기존 커밋을 보존**한 채 이 ZIP 최상위 **내용물**(`hub`, `build`, `api`, `server`, `scripts`, `package.json`, `vercel.json`)을 해당 테스트 저장소 최상위에 복사/덮어쓰고 Commit+Push합니다.
2. 배포 성공 후 로그아웃 상태 또는 시크릿 창으로 `https://lac-build-test.vercel.app/`에 접속하여 **Discord로 로그인 버튼만 있고 회사 개설 코드 입력은 없는지** 확인합니다.
3. 이어 로그인해 기존 HUB/BUILD 진입이 유지되는지 확인합니다. 회사 생성, 실제 글 작성, 데이터 수정은 할 필요 없습니다.
4. 이 검증이 끝나기 전 운영 `lac-hub.vercel.app`은 수정하지 않습니다.

**주의:** 테스트 사이트가 운영 Supabase와 연결되어 있으면 글을 실제 작성/삭제하거나 회사 설정을 수정하면 운영 데이터에 반영될 수 있습니다. 운영 HUB의 기존 Discord/Supabase Vercel 환경변수는 그대로 유지하세요.
