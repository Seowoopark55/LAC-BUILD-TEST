# LAC HUB 통합 기반 · Phase 1

## 적용 범위
- Discord 로그인 이후 회사 가입 여부와 관계없이 LAC HUB 메인에 진입합니다.
- HUB 메인에서 기존 회사 관리 대시보드로 이동하며, 기존 회사 콘솔의 로고 클릭으로 HUB 메인에 돌아옵니다.
- 회사가 없는 계정은 HUB 메인에서 기존 회사 등록/멤버 등록 안내로 이동할 수 있습니다.
- 기존 회사 생성 기능은 아직 개설 코드를 요구합니다. 코드 제거 및 DB 함수 변경은 하지 않았습니다.
- LAC BUILD의 회사 없는 무료 이용 **정책만 표시**합니다. 실행 연결 및 실제 접근 제어는 아직 적용되지 않았습니다.
- LAC COOK, 이용권 등록, 콘텐츠 공개/무료 ON/OFF는 **연결 예정 표시만** 있습니다. 현재 이용권 등록 및 운영자 제어 기능은 없습니다.
- 기존 회사별 데이터 접근/정지 정책 및 회사 멤버 권한 로직을 수정하지 않았습니다.
- `src/platform/catalog.js`는 화면 표시용 카탈로그이며 보안 정책이 아닙니다. 추후 서버/DB에서 권한을 검사해야 합니다.

## 검증 및 배포
- `node scripts/hub-phase1-check.mjs`: 신규 경로의 정적 렌더링 검사.
- `npm run check`: 기존 정적 스크립트의 실행 (기존 대시보드 진입 기본값 한 항목은 신규 HUB 기본값으로 목표 변경).
- `npm run build`: Node 의존성 설치 후 실행. 실제 환경의 Discord 로그인/회사 권한/E2E 검증은 별도 필요.
- 기존 스크린샷 baseline / geometry / DB 이력은 수정하지 않았습니다. 기존 회사 콘솔의 외형은 보존해야 합니다.

## 다음 단계
1. 회사 무소속 로그인 실제 계정 + 기존 회사 계정의 HUB 진입 및 복귀 확인.
2. 공유 DB/기존 AXE BUILD와의 영향 범위 조사 후 서버 측 콘텐츠 정책·이용권 스키마 설계.
3. LAC BUILD 독립 진입 경로 개발 및 기존 AXE BUILD와 데이터·권한 분리 확인.

## Phase 1b · 플랫폼과 회사 관리 네이밍 분리
- LAC HUB는 로그인·통합 메인·운영 플랫폼 명칭으로 유지합니다.
- 회사 관리 콘텐츠 내부 헤더는 `회사 관리`로 표시하고, 헤더 클릭 시 회사 대시보드로 이동합니다.
- 별도의 `← LAC HUB` 버튼으로 통합 메인으로 돌아갑니다.
- 운영자 전용 서비스 관리/레이아웃 화면의 헤더는 `서비스 관리`로 구분합니다.
- 회사별 가입/초기설정 화면의 안내 문구는 회사 관리 문맥으로 분리했습니다.
- Discord 서버의 기존 카테고리 기본 이름, 내부 함수명/키, Supabase 및 다른 서비스는 변경하지 않았습니다.
- 콘텐츠 공개/무료 ON/OFF 및 이용권은 아직 구현되지 않았으며 공유 DB 영향 조회 이후에 적용합니다.

## Phase 1c · 브라우저 뒤로가기 / OAuth 콜백 재진입 방지
- HUB 메인, 회사 관리 진입, 회사 등록 안내, 운영자 관리 화면 전환에 브라우저 History state를 기록합니다.
- HUB → 회사 관리 후 브라우저 뒤로가기는 같은 사이트의 HUB 화면으로 돌아오며, 앞으로가기는 회사 관리로 복귀합니다.
- 회사 관리에서 별도 `← LAC HUB` 버튼을 이용할 때에도 History state가 갱신됩니다.
- 뒤로가기만으로 Discord OAuth를 새로 시작하거나 로그아웃하지 않습니다. 기존 로그인 세션과 DB/권한 코드는 변경하지 않았습니다.
- 기존 Discord 서버 연결 콜백에서 해시를 지울 때 새 History state를 보존합니다.
- 검증: `node scripts/hub-history-check.mjs` + 기존 `npm run check`; 실제 배포/로그인 OAuth는 실환경에서 별도로 확인해야 합니다.
- 주의: 과거에 브라우저에 이미 남아 있던 `localhost:5173` OAuth 에러 주소는 이번 배포로 바뀌지 않습니다. 로컬 서버가 실행 중이지 않다면 해당 URL은 열리지 않습니다. 운영 사이트 주소를 직접 열고 새 화면 이동으로 확인합니다.
